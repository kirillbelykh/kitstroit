# Работа Кирилла с Cursor-агентами KIT

## Схема

```text
Кирилл с Mac, телефона или cursor.com/agents
                    │
                    ▼
              KIT Brain
       приоритеты, задания, проверка
                    │
                    ▼
              KIT Cursor
       реализация, тесты, diff, rollback
                    │
                    ▼
           отчёт и согласования
                    │
                    └──────────────► Кирилл
```

Codex на VPS может обслуживать gate, но не заменяет подтверждение Кирилла в чате.

## Как начать диалог

Открыть в Cursor удалённую рабочую папку:

`/srv/kit-ai/worktrees/cursor-worker`

В обычном Agent-сеансе написать задачу. Постоянное правило автоматически
назначает родительскому агенту роль `kit-brain`.

Пример:

```text
Проверь текущий статус KIT. Выбери один главный приоритет на сегодня.
Реализацию делегируй kit-cursor. Ничего не деплой и не меняй main.
```

Можно явно вызвать агента `kit-brain`, если он доступен в меню субагентов.

## Ежедневный контакт

Утром Кирилл сообщает:

- что изменилось в бизнесе;
- появились ли новые материалы;
- сколько было заявок и какого качества;
- какие решения уже приняты;
- ограничения бюджета или сроков.

`kit-brain`:

1. проверяет данные;
2. выбирает не более трёх приоритетов;
3. делегирует техническую работу `kit-cursor`;
4. проверяет результат;
5. показывает Кириллу только решения и необходимые согласования.

Вечером Кирилл получает:

- что выполнено;
- что доказано тестами;
- что изменилось в метриках;
- что не получилось;
- что требует согласования;
- следующий приоритет.

## Где наблюдать

- Mac: Cursor Desktop, удалённая рабочая папка по SSH.
- Телефон: Cursor Mobile или `cursor.com/agents`, remote machine `kit-neth-1`.
- Код: отдельная task-ветка и review diff.
- Production: меняется только после отдельной L3-фразы Кирилла через wrapper.

## Что Кирилл делает сам

- задаёт бизнес-цели и бюджет;
- предоставляет реальные фото, видео и факты;
- сообщает качество лидов, встречи, сметы и договоры;
- подтверждает уровни `L2` и `L3`;
- принимает решение о merge и deploy;
- пополняет рекламный баланс.

## Git, merge и deploy

L1 не требует отдельного подтверждения: агент создаёт task-ветку, запускает тесты, делает commit, push и draft PR.

Фраза `сделай коммит и пуш, пересобери проект` разрешает commit и push, а «пересобери проект» — явный L3 deploy через wrapper.

Для конкретного PR Кирилл пишет в том же треде `Ок`, `merge` или `мержи`. После green checks и отсутствия конфликтов агент запускает:

```bash
cd /srv/kit-ai/worktrees/cursor-worker
scripts/kit-merge.sh <PR-number>
```

Merge всегда squash; прямой push в `main` и force-push запрещены. Если GitHub не сообщил ни одного check, агент останавливается и просит отдельное явное подтверждение Кирилла перед `--allow-no-checks`.

Для production Кирилл пишет `деплой`, `deploy`, `merge и деплой` или `пересобери проект`. Агент берёт текущий SHA `main` и запускает только:

```bash
cd /srv/kit-ai/worktrees/cursor-worker
scripts/kit-deploy.sh "$(git rev-parse origin/main)"
```

Wrapper блокирует параллельные deploy, принимает только текущий SHA `origin/main`, собирает через Compose с host network, запускает миграции, `make prod-up` и health checks. Он не читает `.env` в чат и не меняет Caddy, firewall, VPN или systemd. Перед deploy wrapper требует, чтобы production `.env` существовал, и оставляет hint проверить актуальность backup.

Cursor Cloud может ограничивать write-операции `gh`. В таком случае агент на VPS вызывает локальный `scripts/kit-merge.sh`; GitHub token используется только в профиле `kit-cursor` и не выводится в чат.

## Аварийная остановка

Если агент работает не на VPS, попал в production, видит неожиданные изменения,
пытается прочитать секреты или не может доказать результат тестами, он обязан
остановиться.

Кирилл пишет:

```text
STOP. Не вноси новых изменений. Покажи pwd, branch, git status и последний diff.
```

После этого изменения проверяются вручную. Production продолжает работать.
